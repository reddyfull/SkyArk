## 2024-05-24 - [Measure-Object Bottleneck & Where-Object String Filtering Logic Bug]
 **Learning:** In PowerShell, using `Measure-Object` in the pipeline is extremely slow compared to wrapping variables in an array and directly calling the `.Count` property (e.g., `@($variable).Count`). Furthermore, using `Where-Object` on a single string to count characters is logically flawed because the pipeline treats the string as a single object, returning 0 matches instead of counting internal characters.
 **Action:** For performance optimization, avoid `Measure-Object` and use `@($variable).Count` for safe array counting or `$hashtable.Count` directly on Hashtables. To correctly and efficiently split strings and count delimiter occurrences without throwing errors on nulls, cast to string and use `-split` (e.g., `([string]$str -split ',').Count - 1`).
