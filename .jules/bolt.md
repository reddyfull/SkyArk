## 2024-05-24 - [Fixing a Logic Bug and Performance Bottleneck in Where-Object Pipeline on Strings]
**Learning:** In PowerShell, using `Where-Object` on a single string (e.g., `"a,b,c" | Where-Object {$_ -eq ','}`) evaluates the entire string as a single object, returning nothing. This leads to logic bugs where character counts are incorrectly reported as 0. Furthermore, checking multiple comma-separated substring occurrences with `-like` on the whole string fails to find all occurrences and incorrectly returns 1, rather than the true number of substrings.
**Action:** When working with strings that represent lists, replace `Where-Object` with array operators by using `-split` to tokenize the string first. For counting commas, use `($string -split ',').Count - 1`. For checking substrings, apply native array filtering: `@(@($string -split ',') -like 'pattern').Count`. This avoids the `Measure-Object` pipeline overhead and corrects the logical flaws simultaneously.
