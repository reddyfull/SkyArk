## 2024-05-18 - Logic Bugs and Pipeline Overhead with Where-Object on Strings
**Learning:** Using `Where-Object` on a single string (e.g., `($string | Where-Object {$_ -eq ','})`) incorrectly evaluates the entire string as a single object rather than its individual characters or parts. It returns nothing if the string isn't an exact match, leading to an incorrect count of zero when pipelined to `Measure-Object`. This not only introduces subtle logic bugs but also adds significant pipeline overhead inside loops.
**Action:** Replace `Where-Object | Measure-Object` pipelines on single strings with the `-split` operator to properly break down the string into an array and evaluate it. Use `([string]$var -split ',').Count - 1` for delimiter counting, or cast to an array and use native filtering like `@([string]$var -split ',' -like '*-Thr*').Count` for matching substrings, avoiding the pipeline completely.
