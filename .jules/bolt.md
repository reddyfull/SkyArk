## 2024-05-24 - [Avoid `Measure-Object` and `Where-Object` in simple counting pipelines]
 **Learning:** PowerShell pipelines silently introduce significant processing overhead compared to native array evaluation and property accesses. Pipelining to `Measure-Object` for simple array lengths is >60x slower than direct `.Count` property access. When applying `.Count` directly to variables that might be scalars, they must be wrapped in an array `@()` first to safely handle `$null` and single items. Also, `Where-Object` evaluating characters within a single string acts on the entire string as one element, returning 0 unless split first.
 **Action:** For performance optimization, avoid `... | Measure-Object` entirely. Use `@($var).Count` safely instead. When counting substrings or delimiters, use the `.Split()` method prior to evaluation instead of `Where-Object`.
