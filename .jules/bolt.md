## 2024-10-09 - [Performance Optimization] Pipeline string evaluation for element counting
**Learning:** In PowerShell, using `Where-Object` on a scalar string (e.g. `$string | Where-Object {$_ -eq ','}`) evaluates the entire string as a single object, incorrectly yielding empty results or errors while adding O(N) pipeline overhead. It does not split or character match natively.
**Action:** Always prefer native operators without pipelines. For counting substrings/characters, use string splitting (e.g., `([string]$var -split ',').Count - 1`). For filtering array properties based on string matches, wrap the left-operand in an array and use `-like` (e.g., `@([string]$var -split ',' -like '*-Thr*').Count`). This provides strict type safety, handles `$null` values safely, drastically cuts overhead, and avoids logic bugs compared to piping strings to `Measure-Object`.
