## 2024-05-24 - Optimizing Measure-Object in PowerShell
**Learning:** In PowerShell loops, passing variables into the pipeline with `Measure-Object` incurs a severe performance penalty (almost ~100x slower) compared to using direct native property access. However, directly accessing `.Count` can be unsafe for unknown input types before PowerShell 3.0 or when dealing with potential `$null`s. Wrapping the variable in nested arrays (`@(@($var))`) safely forces any value into an array without flattening existing arrays, allowing `.Count` to safely evaluate on scalars, nulls, and collections while eliminating the pipeline overhead.
**Action:** When refactoring element counting inside frequent loops, safely remove `Measure-Object` using `@(@($var)).Count`. Also be aware that `($var | Where-Object {$_ -eq ','} | Measure-Object).Count` to count chars in a string produces 0 because strings don't enumerate in pipelines this way - use `.Split(',').Count - 1` instead.
