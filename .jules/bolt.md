## 2024-08-12 - [Removed Measure-Object Pipeline Overhead]
**Learning:** PowerShell pipelines (`| Measure-Object`) allocate significantly more memory and take longer than direct property access (`.Count`) or array wrapping. For primitive counting logic in tight loops, pipelines cause a significant bottleneck (~15ms vs ~2300ms for 1000 iterations), especially with large IAM policy arrays. Replacing `.Split()` with `-split` is safer for handling `$null` values, but wrapping with native operators (`@($var -eq ',')`) completely bypasses the pipeline penalty and maintains the original string evaluation semantics.
**Action:** Always favor `.Count` with array wrapping (`@($var).Count`) instead of `| Measure-Object`. When replacing `Where-Object` on collections of simple types, favor PowerShell native filtering (`-split` with strings or `@(@($array) -eq 'val').Count` with arrays) to maximize performance while retaining behavior safely.
