## 2026-07-21 - [PowerShell Pipeline Scalar Filtering Absorption & Measure-Object Bottleneck]
**Learning:** Using `Where-Object` on a scalar string (e.g. `$string | Where-Object {$_ -eq ','}`) evaluates the string as a single item. If the condition doesn't match the *entire* string, it returns `$null`. Furthermore, piping into `Measure-Object` for simple length operations or counting is highly inefficient due to pipeline overhead (O(N) operation overhead). Replacing pipelines with native array filters or string methods produces extreme speed-ups (over 20x).
**Action:** When calculating string delimiter occurrences, never use `Where-Object`. Use `.Split(',').Count - 1`. When counting matches using wildcards, preserve exact array filter semantics safely without pipeline overhead by explicitly wrapping the string in an array: `@(@($string) -like '*-Thr*').Count`. For checking lengths of arrays or values globally, bypass `Measure-Object` entirely and prefer `@($variable).Count`.
