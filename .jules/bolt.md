## 2024-03-24 - [Avoid Pipeline Overheads and Logical Traps with Strings]
**Learning:** In PowerShell, using `Where-Object` and `Measure-Object` in pipelines is not only slow but can cause logical bugs when dealing with scalar strings. For example, piping a string to `Where-Object` treats the string as a single item; searching for a comma (`$_ -eq ','`) will result in 0 matches even if the string contains commas. Additionally, `Measure-Object` introduces significant pipeline overhead compared to direct property access like `@($var).Count`.
**Action:** When counting elements or checking conditions, avoid pipeline cmdlets. For arrays, wrap them and use `.Count` (e.g. `@($array).Count`). For finding delimiters or counting specific characters in strings, use native string methods like `.Split(',')` and calculate the length, or cast the string explicitly to a char array before matching.
