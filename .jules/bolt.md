## 2024-10-11 - PowerShell String Pipeline Logic Bug and Performance Bottleneck
**Learning:** In PowerShell, evaluating a scalar string via a pipeline like `($string | Where-Object {$_ -eq ','})` fails completely because the entire string is treated as a single object, resulting in null/empty returns. This creates silent logic bugs when counting character occurrences, compounded by severe performance overhead from the pipeline and `Measure-Object`.
**Action:** Always avoid piping scalar strings into `Where-Object` for character counting. Instead, use the native `-split` operator (e.g., `($string -split ',').Count - 1`) to correctly evaluate delimiters and eliminate the O(N) pipeline overhead. When filtering array items, use native array wrappers and operators (e.g., `@(@($string -split ',') -like 'pattern')`) rather than `Where-Object`.
