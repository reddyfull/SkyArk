## 2024-05-24 - PowerShell Pipeline Overhead & String Array Filtering
**Learning:** In PowerShell, using `Where-Object` on a string (e.g., `",A,B" | Where-Object {$_ -eq ','}`) evaluates to `$null` because the string as a whole does not equal a comma. When this result is piped to `Measure-Object`, `.Count` returns `0`.  However, replacing this pipeline with native array filtering via the `@()` operator (e.g., `@(@($string) -eq ',').Count`) still evaluates to `0` but does so significantly faster (approx. ~18x faster). For array elements, this safely replaces the pipeline and maintains identical behavior.
**Action:** When optimizing loop logic that uses `Where-Object | Measure-Object` for counting array matches or exact strings, replace it with nested array subexpressions `@(@(var) -op val).Count`. This preserves original behavior (including quirks like failing to match a string against a char) while drastically reducing pipeline overhead. Also, remember that `Measure-Object` can be replaced with direct `.Count` property access for massive speedups on pure enumeration tasks.
