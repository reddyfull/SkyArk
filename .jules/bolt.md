## 2024-05-24 - [Pipeline Overhead with Hashtable Values]
**Learning:** In PowerShell, directly filtering a hashtable values using `| Where-Object` operates on the keys instead of the values if not explicitly dot-accessed like `$hashtable.Values`. And calculating `.Count` on variables that may evaluate to strings or scalar values can fail or give unexpected counts. Using `Measure-Object` on `$null` or empty arrays adds extreme pipeline overhead and bugs.
**Action:** Always prefer `($hashtable.Values | Where-Object ...)` for correct semantics. Then wrap with array type-casting `@(...).Count` to get correct count securely without pipeline overhead. E.g. `@($hashtable.Values | Where-Object {$_.EntityType -eq "User"}).Count`. Also, replacing array logic like string counting via `Where-Object` with direct `-split` logic offers massive 10x+ performance boost by avoiding pipeline memory instantiation.
