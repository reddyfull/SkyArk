## 2024-05-18 - Pipeline Overhead and Array Filtering Semantics in PowerShell
**Learning:** In PowerShell, using pipelines (`|`) with `Measure-Object` for simple counting introduces significant overhead, which is an architectural anti-pattern for performance-critical loops. Direct access to the `.Count` property is faster, but to safely count both arrays and scalar variables without losing the pipeline semantics (where a string is a 1-item list), variables should be explicitly cast to arrays, e.g., `@(@($var)).Count`. Also, when calculating substring occurrences or string filtering previously done by `| Where-Object`, using `.Split()` or array matching operators (`-eq`, `-like`) correctly mimics the original behavior while avoiding the pipeline entirely.
**Action:** Always prefer direct property access like `@(@($var)).Count` over `| Measure-Object`. Use array operators for filtering variables instead of `Where-Object` within performance-sensitive paths.
