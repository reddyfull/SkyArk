## 2024-05-14 - [PowerShell Pipeline Overhead and Hashtable Filtering]
**Learning:** In PowerShell, using the pipeline (`|`) inside loops—especially nested ones or when processing large collections—introduces massive O(N^2) overhead because it allocates and wraps objects (`PSObject`) individually for every iteration. For simple filtering and counting, methods like `Where-Object { ... } | Measure-Object` should be replaced with native array operators and `.Count` property access (e.g., `@(@($var) -eq 'val').Count`). Furthermore, directly piping a dictionary/hashtable to `Where-Object` parses the raw `System.Collections.DictionaryEntry` objects, resulting in empty sets when attempting to filter by custom object properties inside the values.
**Action:** When filtering dictionaries, always iterate over the `.Values` property (`$dict.Values | Where-Object`). Replace all `... | Measure-Object` pipelines with direct `@(...).Count` access to avoid pipeline overhead and instantiate native integer types directly. When filtering an array simply to count matches, avoid pipeline `Where-Object` entirely and use array filtering operators instead: `@(@($array) -match 'pattern').Count`.
