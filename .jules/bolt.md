## 2024-05-18 - [AWStealth String Parsing Pipeline Bottleneck & Bug]
**Learning:** Using `Where-Object` on a string (e.g., `$str | Where-Object {$_ -like '*-Thr*'}`) evaluates the entire string as a single object, returning 0 or 1. While this logic is technically flawed for counting *multiple* occurrences within a comma-separated string, the application depends on this exact behavior (returning 0 or 1). Piping strings through `Where-Object` and `Measure-Object` in a tight loop creates a severe O(N^2) pipeline bottleneck.
**Action:** Replace slow string pipeline checks (`$str | Where-Object {$_ -like 'pattern'} | Measure-Object`) with highly efficient native boolean casts (`[int]($null -ne $str -and $str -like 'pattern')`). This achieves identical functional logic (0 or 1, handles null safely, handles array edge cases identically) but runs ~25x faster by avoiding pipeline overhead.
