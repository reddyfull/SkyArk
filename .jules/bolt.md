## 2024-05-24 - Safely eliminating PowerShell pipeline overhead

**Learning:** Pipeline operations (`Where-Object | Measure-Object`) in tight loops are a massive performance bottleneck in PowerShell. However, replacing them with string methods like `.Split()` or `[regex]::Matches()` can subtly break logic if the code relied on array filtering semantics (where a string is treated as a 1-item array, so `($str | Where-Object {$_ -eq ','})` incorrectly returns 0 but `($str | Where-Object {$_ -like '*-Thr*'})` correctly evaluates the whole string). Also, strings vs arrays evaluation is tricky because `|` will iterate arrays but evaluate strings as scalars. Furthermore, `($null).Count` evaluates to 0 safely, whereas pipeline can eat `$null` inputs.

**Action:** Use native PowerShell array filtering and property access to replace pipelines. Wrap variables explicitly in arrays `(@(@($var) -like 'pattern').Count)` to guarantee array semantics and safely handle `$null`, scalars, and actual arrays while eliminating pipeline overhead (often a 10x speedup). For simple counting, prefer `$var.Count` (falling back to array cast `@($var).Count` if needed) over `$var | Measure-Object`.
