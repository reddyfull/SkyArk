## 2024-03-27 - [PowerShell Pipeline Optimization]
**Learning:** Avoid piping `$hashTable` directly to `Where-Object` (it tests against `System.Collections.DictionaryEntry` objects) or `Measure-Object` because it evaluates the hash table itself rather than its contents, causing incorrect results. Directly accessing `Count` and filtering on `$hashTable.Values` prevents these logic errors and drastically reduces overhead. Additionally, use `-split` rather than `Where-Object` to count delimiter occurrences within a string as it executes significantly faster while avoiding logic bugs.
**Action:** Replace `Where-Object` and `Measure-Object` usage directly on hash tables with `$hashTable.Values | Where-Object` or `$hashTable.Values.Count`. Use `-split` for delimiter counting instead of `.Split()` or `Where-Object`. Ensure to force the operand to an array with `@()` before accessing `.Count` on scalar variables to prevent logic bugs.
