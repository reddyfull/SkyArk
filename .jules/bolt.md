## 2024-11-20 - [Performance: Optimizing Where-Object | Measure-Object with String splits]
**Learning:** Using `Where-Object` on a single string to count characters or match patterns evaluates the entire string as a single object and returns nothing, leading to logic bugs. Also, pipelines incur significant overhead. We can optimize element counting and filtering by replacing `Where-Object` and `Measure-Object` on comma-separated strings with `-split` and native array filtering (`-like`), safely evaluating the string and drastically reducing pipeline overhead.
**Action:** Always use `-split` for correctly identifying and counting occurrences of a delimiter within a string, and wrap arrays/split strings natively when checking patterns (e.g., `@(@([string]$var -split ',') -like '*-Thr*').Count`).
