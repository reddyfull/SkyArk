## 2025-02-20 - [PowerShell Pipeline String Scalar Logic and Overhead]
**Learning:** Using `Where-Object` and `Measure-Object` in the pipeline on a string scalar that should be treated as an array of characters or delimited parts evaluates incorrectly in PowerShell. Since the string is sent as a single object through the pipeline, `Where-Object {$_ -eq ','}` evaluates to `$false` for the whole string, returning `$null`, resulting in a `.Count` of 0. Likewise, pipeline overhead drastically impacts performance in high-iteration counting scenarios.
**Action:** Always avoid pipeline filtering for string delimiter counting (use `.Split(',').Count - 1` instead) or native array matching operators when evaluating properties (`@(@($var.Split(',')) -like '*-Thr*').Count`). Replace all simple `($collection | Measure-Object).count` with direct property access `@($collection).Count` to safely and cleanly bypass pipeline overhead while handling `$null`, scalar strings, and arrays natively.
