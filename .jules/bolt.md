## 2024-05-15 - Array Property vs Pipeline Measure-Object and Where-Object Logic Bugs
**Learning:** In PowerShell, counting elements by piping to `Measure-Object` adds significant pipeline overhead. Accessing the `.Count` property directly on variables or expressions, especially when wrapped in an array `@()`, is vastly faster (e.g. ~15ms vs ~2300ms for 1000 iterations). Additionally, piping single strings to `Where-Object` (e.g., `"a,b,c" | Where-Object {$_ -eq ','}`) evaluates the whole string as one object, leading to incorrect logic when trying to count delimiter occurrences.
**Action:** Replace `| Measure-Object` with `@(...).Count` for efficient and null-safe element counting. Replace string `Where-Object` filtering with the `-split` operator (e.g., `($string -split ',').Count - 1`) to correctly evaluate and count characters in strings while avoiding fatal runtime errors.
