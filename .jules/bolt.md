## 2024-05-18 - Replacing `Where-Object | Measure-Object` with `@(@(..)).Count` in PowerShell
**Learning:** Piping arrays through `Where-Object` and `Measure-Object` in PowerShell incurs significant overhead because of pipelining. Using native array filtering by casting elements into an array (`@($var)`) and applying comparison operators (e.g., `-eq`, `-like`) before calling `.Count` is much more performant. However, for dictionaries/hashtables where we need to filter the objects they hold rather than dictionary entries, accessing the `.Values` property prior to filtering is required for correctness. Also note that for custom objects, filtering by properties needs to either stick to `Where-Object` before checking `.Count` or use the correct native array casting, but it's important to not cast objects to strings inadvertently. For performance, we replaced `.Count` calculations using `Measure-Object` with explicit `.Count` property checks and direct `Where-Object` (or native operators where safe) array accesses to avoid huge O(N) penalties during loops and summarizations.
**Action:** When filtering or counting items in PowerShell performance optimizations, avoid using `Measure-Object`. Directly rely on `.Count` by wrapping results in arrays `@(expression).Count` to handle `$null`, scalars, and arrays appropriately without pipelining overhead.
