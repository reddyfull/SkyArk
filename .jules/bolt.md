## 2024-03-24 - [Measure-Object Overhead and Logic Flaws]
 **Learning:** Using `| Measure-Object` for counting in PowerShell pipelines introduces significant performance overhead and can cause logic bugs. For example, `( $inlineRolePolicy | Measure-Object).count` on an empty array evaluates to `1` which is incorrect. A notable logic bug exists where `$inlineRolePoliciesCounter += $($inlineRolePoliciesCounter | Measure-Object).count` is used instead of `$inlineRolePoliciesCounter += $($inlineRolePolicy | Measure-Object).count` or rather `$inlineRolePolicy.Count`. Additionally, for strings, splitting with `-split` is safer and more performant than pipeline filtering.
 **Action:** Refactor pipelines like `($var | Measure-Object).Count` to direct `.Count` property access if they are collections/arrays. For string delimiter counting, use the `-split` operator instead of `Where-Object` (e.g. `([string]$var -split ',').Count - 1`). Be careful when operating on strings vs arrays. Ensure variable references are correct when fixing bugs.
