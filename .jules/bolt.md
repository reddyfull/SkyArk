## 2024-08-20 - [Measure-Object vs @().Count Pipeline Overhead]
 **Learning:** Using `| Measure-Object` for counting array elements or properties in PowerShell incurs massive pipeline overhead (e.g., 7000ms vs 35ms for 1000 iterations) and is a significant performance bottleneck. In addition, using `Where-Object` on a scalar string to check for exact match or count characters (e.g., `($str | Where-Object {$_ -eq ','} | Measure-Object).Count`) evaluates the entire string as a single object, returning 0 and causing logic bugs.
 **Action:** Prefer using array filtering directly with native operators (e.g., `@(@($var) -like 'pattern').Count`) or string splits (`[string]$str -split ','`). Replace `.count` with `.Count` for consistency, and avoid `Measure-Object` entirely when simply fetching array length or filtering elements. Replace `+=` on arrays with generic lists or pipeline assignments where possible, though the most immediate gain here is removing pipeline filtering on strings.
