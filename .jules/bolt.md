## 2024-06-15 - [PowerShell Pipeline Overhead and Array Concatenation Bottlenecks]
**Learning:** In PowerShell, using `Where-Object` paired with `Measure-Object` in heavily iterated loops adds immense pipeline overhead (e.g., parsing comma-delimited strings in `AWStealth.ps1`). Native array operators (`@($arr) -eq 'val'`) bypass this pipeline completely, yielding a 15x speedup. Furthermore, iterating directly over object properties using `.Count` is much faster than piping to `Measure-Object`. Lastly, accumulating elements via `+=` with arrays (`@()`) scales `O(N^2)` as it creates a new array every iteration; replacing these with `System.Collections.Generic.List[psobject]` and `.Add()` eliminates this bottleneck in scripts like `AzureStealth.ps1`.
**Action:** Always prefer native array match/equality operators (`-match`, `-like`, `-eq`) coupled with `.Count` for simple counting logic in loops, rather than `Where-Object | Measure-Object`. When populating collections iteratively, always initialize as `System.Collections.Generic.List[T]` rather than `@()` array types to ensure linear time scaling.
